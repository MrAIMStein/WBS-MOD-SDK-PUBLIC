# 制作、调试与发布模组

本指南从一个已安装 SDK 的作者工程开始，带你创建模组、制作内容、在游戏中调试并生成发布包。环境准备见 [SDK 安装](SDK安装.md)。

## 创建自己的模组

1. 打开 `WBS/模组/新建模组`。
2. 选择人物模型、玩法、物品或界面，填写英文目录标识、模组名称和作者。
3. 点击“创建模组”，等待 Unity 编译及自动资源绑定完成。
4. 在 Project 中找到 `Assets/Mod/{KeyName}/Editor/Build.asset`，这是后续使用的打包配置。

人物模型通过制作器生成，可无需编写入口代码。其他类型会生成 C# 入口和对应示例资源，你可以从这些代码继续开发；同一个自定义入口模组也可以同时提供玩法、物品、人物和 UI。

`KeyName` 是英文目录标识，使用英文字母开头，仅包含英文字母、数字和下划线，最多 64 位。向导会生成模组 UUID。首次发布后保持 UUID、KeyName 和人物 ID 不变，更新通过模组 `Version` 区分。直接复制官方示例目录会连同示例身份一起复制，建议先用向导创建自己的模组，再迁入需要的内容。

作者资源统一放在自己的目录中，例如：

```text
Assets/Mod/MyMod/
  Art/Models/                     源模型、贴图
  Art/Materials/                  作者材质
  Art/Prefabs/                     人物、物品、界面等 Prefab
  Editor/                         打包配置、人物制作配方
  Scripts/                        入口和运行时脚本、asmdef
  data/                           需要随模组分发的数据
```

使用模型、材质或 Prefab 前，将作者自有依赖放到该模组目录；公共资源直接引用 SDK。保留资源的 `.meta`，它们与已发布内容的身份和引用有关。

## 制作人物模型

1. 把模型和贴图导入本模组目录。FBX 在导入设置中配置 Humanoid Rig，并确认 Avatar 有效；VRM 按 [VRM 模型导入](VRM模型导入.md) 操作。
2. 打开 `WBS/角色/角色制作工具`，新建或选择人物制作配置，使用“模组人物”模式。
3. 填写与打包配置一致的模组 KeyName、UUID，设置人物 ID、名称和素材授权记录。人物 ID 的命名规则与 KeyName 相同。
4. 选择美术源模型和 SDK 的完整人物模板，调整模型偏移、比例、布娃娃质量和人物视角。
5. 按需选择“创建 Toon 材质副本”，再点击“检查”。解决报告中的错误后，点击“生成完整人物”。
6. 生成结果位于 `Art/Prefabs/Character_Multi/{ModelId}.prefab`。将对应配方填入打包配置的 `CharacterRecipes`，确认成品已生成并保存。

源模型需要包含一个有效 Humanoid Avatar。完整游戏人物 Prefab 已包含控制与网络结构，制作时选择美术源模型作为输入。

模型模式会自动登记标准人物目录中的完整成品；也可以在 `ModelPrefabs` 中明确指定。打包操作使用现有成品，调整配方后需要先重新生成、保存，再打包。

人物制作工具给出的碰撞和布娃娃尺寸是初值。在游戏中检查动画、持物、第一与第三人称视角、预览、头像及倒地表现，再决定是否调整。可以用“读取人物视角”将成品视角读回配方，或用“应用视角配置”保存配方中的视角。

### 调整材质与成品

材质副本保存在作者目录中，原模型材质继续保留。使用 `WBS/Toon` 和人物预设作为起点，再检查光照、透明、裁切和描边。旧 `UGL/Toon` 材质可以通过制作侧转换处理，报告中无法等价转换的参数需要手动调整。自定义 Shader 可以继续使用，但要保留其依赖并在目标游戏中检查渲染效果。

后续修改优先保存在源模型、作者材质和制作配方中。再次点击“生成完整人物”会沿用既有成品的游戏结构；采用新 SDK 模板时使用“刷新到当前模板”。工具发现成品被手工修改时会报告差异，先备份并处理冲突，再继续更新。完整步骤见 [升级与游戏更新](升级与游戏更新.md)。

## 开发玩法、物品与界面

从向导生成的入口和资源开始修改，使用 `ModApi.For(Context)` 获取所属模组的 API。在入口 `OnLoad()` 中登记内容，完成后返回成功；读取资源、打开 UI 和联机逻辑按各接口的生命周期执行。

- 玩法：学习设置、地图、回合状态和 Pad 页面；影响胜负的状态由服务端处理。
- 物品：在服务端检查真实持有者，再执行使用效果和同步。
- 界面：通过 `api.Ui.RegisterMenuPanel(...)` 登记主界面，通过 `OpenPanel`、`OpenView`、`OpenPopup` 主动打开其他 UI。

具体签名、资源地址、Harmony 和会话清理方式见 [API 参考](接口协议.md)，五个官方示例的 README 列出关键脚本与修改点。运行时脚本放在本模组的程序集内，Editor 工具放在 `Editor` 目录；新增可挂载组件时，使用与类名相同的 C# 文件，编译完成后再挂到 Prefab。

## 配置打包内容

打开 `WBS/模组/打包工具`，在“制作配置”选择 `Editor/Build.asset`。向导已填写基础配置，先核对名称、作者、版本和说明，再根据内容调整下列字段。

| 配置 | 何时设置 |
| --- | --- |
| `Info.Version` | 每次发布更新时修改模组版本，例如 `1.0.1` |
| `Info.Dependencies` | 使用其他模组时填写其 UUID，并让玩家安装依赖 |
| `Info.MinGameVersion` | 内容依赖某个游戏版本时填写最低数字版本，例如 `0.3.2` |
| `Mode` | 人物自动入口用 `Model`；作者代码入口用 `Custom` |
| `CharacterRecipes` / `ModelPrefabs` | 指定已制作完成的人物 |
| `ResourceEntries` | 明确选择资源入口；留空时收集模组根内的可打包资源 |
| `DataSourceDirectory` | 需要分发数据时选择源目录；默认使用模组目录下的 `data/` |
| `IconSourcePath` / `Info.IconPath` | 配置模组图标 |
| `AdditionalAssemblyNames` | 需要额外作者程序集时填写程序集名，不带 `.dll` |
| `ExternalDlls` | 确实需要分发第三方 DLL 时明确选择，并保留其许可 |
| `OutputRoot` | 设置发布目录存放位置，默认 `Build/Mods` |

自定义入口程序集为 `{KeyName}ModEntry`，入口类为 `WBS.Client.Mod.{KeyName}.{KeyName}Mod`，继承 `ModBase`。使用向导创建时会自动生成对应名称与程序集引用。

SDK 和游戏提供的 DLL 已由游戏加载，打包器会排除这些宿主 DLL。额外作者程序集及第三方 DLL 按配置导出；网络脚本需要通过 Mirror 编译织入，检查失败时按报告处理对应脚本和引用。

## 打包并在游戏中调试

1. 保存资源和脚本，确认 Console 没有编译错误。
2. 在打包工具中点击“检查”，处理错误并阅读警告。
3. 点击“选择 exe”，选择完整 Windows x64 游戏中的 `WBS.exe`，保留游戏目录中的配套文件。
4. 关闭正在运行的游戏，再点击“打包并启动调试”。工具完成打包、安装并以开发模式启动游戏。
5. 在游戏中确认内容已加载，体验人物、玩法、物品或界面；修改后关闭游戏，再重新打包并启动。

开发模式使用独立的 `WBS_Dev` 数据目录，与你正常游玩的配置分开保存。新发现的开发模组默认启用；如你曾禁用它，在模组管理页重新启用。游戏和 SDK 无需版本号完全相同，工具会检查 API、平台和开发环境要求。

调试启动会保留作者程序集的调试符号。游戏构建支持 Unity 脚本调试时，可以用 Visual Studio 或 Rider 附加 WBS 进程并设置断点；普通游戏构建可通过实际游玩和日志定位问题。会话记录和游戏日志可在 `WBS_Dev/diagnostics/SDKDebugSessions/` 查阅。联机调试需要 Steam 环境及参与账号的游戏访问权。

## 生成发布包并分享

1. 确认模组名称、版本、说明、依赖和素材署名正确，关闭 `DebugBuild`。
2. 选择位于 `Assets`、`Packages` 之外的输出根目录，点击“检查”→“打包发布目录”。
3. 点击“打开成品目录”，确认生成了 `{KeyName}-{Version}` 文件夹。
4. 在目标游戏中安装这份正式成品，检查加载及实际表现；联机内容还应使用两位玩家、一致的模组成品检查同步与权限。
5. 将整个成品文件夹压缩分享，或在游戏的“模组管理”→“发布”页将它选为上传内容。

发布目录示意：

```text
MyMod-1.0.0/
  modinfo.json
  MyModModEntry.dll                入口 DLL，按模组内容生成
  bundle/                         有资源时包含 catalog 和全部 bundle
  dll/                            可选辅助程序集、第三方 DLL
  data/                           可选数据
  icon.png                        可选图标
  mod-build-report.json           打包报告
```

分享时保留全部成品文件。输出目录已存在时，工具会要求你更换输出位置或提高模组版本；打包失败会保留原有成品。出现错误时先查看打包窗口和 `mod-build-report.json`，确认资源、引用、入口与依赖完整。

发布更新时保持模组身份，提醒玩家替换完整包，并说明新增依赖或最低游戏版本要求。安装步骤可以按下节整理到你的发布页。

## 交给玩家安装

发布页应写明模组作用、版本、所需游戏、依赖、操作方式与素材署名。可以把以下本地安装步骤提供给玩家：

1. 启动游戏，打开“模组管理”→“管理”→“本地文件夹”，再退出游戏。
2. 将完整成品解压到这个目录中。每个模组为一个直接子文件夹，`modinfo.json` 位于该子文件夹顶层。
3. 重新启动游戏，启用模组与所需依赖，将依赖排在使用它的模组之前，点击“保存”。
4. 按“重启后生效”的提示退出并重新启动游戏。

工坊用户可以通过“模组管理”→“发布”页的“浏览创意工坊”订阅；等待 Steam 下载完成后，同样需要在游戏中启用、保存并重启。

人物模组可在多人等待大厅中按默认键 `Esc` →“切换模型”选择人物。提供了主界面的模组，可在管理页选中后点击“面板”。玩法和物品按你的发布说明使用。联机参与者应使用相同的成品和启用设置。

更新本地包时先退出游戏，将旧版本移到安装目录之外，再复制完整新包。同一模组只保留一份版本；本地与工坊副本身份相同时，游戏优先使用本地副本。卸载前先取消启用、保存并重启，再退出游戏移除本地包，或在 Steam 中取消订阅；同时处理依赖该模组的其他内容。

若列表中找不到模组，先检查解压层级；能看见却无法使用时，确认启用和重启，查看加载提示。请玩家反馈游戏版本、模组版本、错误提示和重现步骤。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 打包找不到资源或依赖超出模组目录 | 作者资产及其依赖是否位于 `Assets/Mod/{KeyName}/`，公共资源是否来自 SDK |
| 新配方未反映到成品 | 是否已点击生成并保存人物，打包配置是否选择正确成品 |
| 模组出现在列表中但没有内容 | 是否启用并重启，入口是否加载成功，查看游戏日志 |
| 点击“面板”提示没有主界面 | 是否选择且成功加载了该模组，入口是否登记主界面 |
| 联机使用或渲染与编辑器不同 | 使用正式成品在游戏中检查，依据网络错误或材质报告调整 |

游戏更新后的处理与人物模板升级见 [升级与游戏更新](升级与游戏更新.md)。

## 可选：批量打包

有多个模组或需要自己的自动化流程时，可以使用编辑器入口：

```text
Unity.exe -batchmode -projectPath <作者工程> -buildTarget Win64 -executeMethod WBS.Client.Editor.ModSDK.ModBuildService.BuildFromCommandLine -modProfile Assets/Mod/MyMod/Editor/Build.asset -modOutput <输出根目录>
```

多个配置用分号分隔，并给整段路径列表加引号。等待工程导入、编译完成后执行，避免两个任务同时写入同一工程；命令会返回成功或失败退出码。
