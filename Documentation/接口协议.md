# 模组 API 参考

本页介绍模组 API `2.1.0` 的入口、资源加载、人物与玩法登记、屏幕 UI，以及 Harmony 补丁注册。第一次制作模组请先阅读 [使用说明](使用说明.md)，再按需要查阅下面的接口。

## 1. 创建入口并取得 API

使用 `WBS/模组/新建模组` 创建模组。人物模型模式会自动生成登记入口；玩法、物品和界面模式会生成可编辑的 C# 入口。

自定义入口继承 `ModBase`，在 `OnLoad()` 中通过 `Context` 取得本模组 API。下面是一个界面模组的入口：

```csharp
using WBS.Client.Common.Mod;
using WBS.Client.Logic.ModSupport;

namespace WBS.Client.Mod.MyMod
{
    public sealed class MyModMod : ModBase
    {
        public override bool OnLoad()
        {
            var api = ModApi.For(Context);
            api.Ui.RegisterMenuPanel(
                "Main", "我的模组", "Art/Prefabs/Panel.prefab");
            return true;
        }
    }
}
```

这个例子假设 `Assets/Mod/MyMod/Art/Prefabs/Panel.prefab` 已存在。入口程序集为 `MyModModEntry`；入口类型遵循 `WBS.Client.Mod.{KeyName}.{KeyName}Mod` 命名，公开且具有无参数构造函数。新建向导会设置这些名称。

`Context` 在 `OnLoad` 前由游戏提供，构造函数中不要使用它。返回 `true` 表示完成登记；返回 `false`、抛出异常或登记失败时，模组不会加载成功，已经登记的内容会被撤销。

### Context 常用成员

| 成员 | 用途 |
| --- | --- |
| `UUID`、`KeyName` | 当前模组身份 |
| `Directory` | 当前模组成品目录 |
| `Resources` | 加载当前模组打包的资源 |
| `Assemblies` | 查找当前模组入口及辅助程序集中的类型 |
| `Log` | 输出带模组身份的日志，可调用 `Info`、`Warning`、`Error` |
| `State` | 当前加载状态；主动打开 UI 时应已处于 Loaded 状态 |

每个模组都有自己的 Context。模组卸载后不要继续用旧 Context 加载资源、登记内容或打开界面。

## 2. 登记人物、玩法、物品和主界面

所有登记调用都放在 `OnLoad()` 中，不能等到异步回调或对局开始后再登记。一个自定义入口可以组合多种内容；新建时选择的类型只是起点。

| 调用 | 定义 | 返回值 |
| --- | --- | --- |
| `api.RegisterCharacter(definition)` | `ModCharacterDefinition` | 完整人物 ID |
| `api.RegisterGameplay(definition)` | `ModGameplayDefinition` | 玩法 UUID |
| `api.RegisterItem(definition)` | `ModItemDefinition` | 完整物品 ID |
| `api.Ui.RegisterMenuPanel(id, title, prefabAddress)` | 本模组的主界面 | `void` |

### 人物

```csharp
api.RegisterCharacter(new ModCharacterDefinition
{
    ModelId = "Hero",
    PrefabAddress = "Art/Prefabs/Character_Multi/Hero.prefab"
});
```

`PrefabAddress` 指向制作工具生成的完整人物 Prefab，不能直接填写原始 FBX 或只有外观的模型。人物模型模式会根据打包配置自动登记，通常不需要手写这段代码。`ModelId` 是本模组内的人物标识，发布后应保持稳定。

### 玩法

`ModGameplayDefinition` 使用以下字段：

| 字段 | 含义 |
| --- | --- |
| `Info` | `WBGInfo`，包含玩法 `UUID`、`KeyName`、`Version` |
| `SettingsType` | 继承 `WBGSettings` 的作者设置类型 |
| `ControllerPrefabAddress` | 挂有作者 `WBGControllerBase` 的联网控制器 Prefab |
| `ConfigAddress` | 玩法配置资源，地图清单要与 `Maps` 一致 |
| `RulePanelAddress` | 规则页面 Prefab |
| `PadAppsAddress` | Pad 应用配置资源 |
| `Maps` | `ModMapDefinition` 清单：`MapId`、`PrefabAddress`，可选 `MetadataAddress` |
| `BackgroundAddress` | 可选背景资源 |
| `DataDirectory` | 可选玩法数据目录 |

玩法的配置中不直接登记物品；需要物品时另外调用 `RegisterItem`。设置类型必须位于本模组入口或打包配置明确包含的辅助程序集内。完整登记和控制器实现见 [石头剪刀布示例](https://github.com/MrAIMStein/WBS-MOD-SDK-PUBLIC/blob/main/Examples/WBSModExamples/Assets/Mod/WBSExampleGameplay/README.md)。

### 物品

```csharp
api.RegisterItem(new ModItemDefinition
{
    ItemId = "Counter",
    InfoAddress = "StaticData/Counter.asset",
    DataModelType = typeof(CounterData),
    BehaviourPrefabAddress = "Art/Prefabs/Counter.prefab"
});
```

`CounterData` 是作者定义、继承 `ItemDataModel` 的类型。行为 Prefab 根节点须有且仅有一个作者 `ItemBehaviour`；物品信息的 `ItemId`/`ItemShortId` 要与登记的 `ItemId` 一致。数据模型类型必须属于本模组入口或明确包含的辅助程序集。

可选字段 `GameplayUuid` 为空时表示通用物品；填写时须先登记本模组的对应玩法，不能挂到其他模组的玩法下。人物和物品的完整 ID 包含模组身份；不要手工拼接或复用其他模组的 ID。物品数据、行为和授权展示见 [联网计数器示例](https://github.com/MrAIMStein/WBS-MOD-SDK-PUBLIC/blob/main/Examples/WBSModExamples/Assets/Mod/WBSExampleItem/README.md)。

### 管理页主界面

```csharp
api.Ui.RegisterMenuPanel("Main", "我的模组", "Art/Prefabs/Panel.prefab");
```

每个模组最多登记一个主界面，重复登记会导致加载失败。玩家在“模组管理 → 管理”中选中模组，点击“保存更改”左侧的“面板”按钮打开它。未登记主界面也可以正常加载其他模组内容。

主界面根节点须有 `RectTransform`。标题、装饰、分页和关闭按钮都由作者保存在 Prefab 中；`title` 用于标识入口，不会替作者生成标题栏。关闭按钮通过下文的 `ModUiSession.Close()` 关闭本次界面。

## 3. 加载资源与查找类型

### 资源地址

资源地址通常使用相对于 `Assets/Mod/{KeyName}/` 的路径：

```csharp
using var handle = Context.Resources.Load<UnityEngine.GameObject>(
    "Art/Prefabs/Counter.prefab");
UnityEngine.GameObject prefab = handle.Asset;
```

也可以使用 `Assets/Mod/{KeyName}/...` 完整地址。资源必须属于当前模组并已打包，不能用地址访问其他模组、SDK 包、任意磁盘文件或远程 URL。

| 接口 | 使用方式 |
| --- | --- |
| `Load<T>(address)` | 同步加载，返回 `ModAssetHandle<T>`，通过 `Asset` 读取资源 |
| `LoadAsync<T>(address)` | 返回同类句柄，先 `await handle.Task`，再读取 `Asset` |
| `handle.Dispose()` | 释放本次资源引用 |

实例化 Prefab 后，句柄应保留到实例销毁。`using` 适合在作用域内读取资源；不要在作用域结束、句柄已经释放后继续使用该资源或实例。模组卸载会释放尚未归还的句柄，但自行创建的 GameObject 和事件订阅仍需自行清理。

### 作者程序集

`Context.Assemblies.All` 包含本模组的入口及已验证的辅助程序集。`Context.Assemblies.GetType(fullName)` 在这些程序集内查找类型：不存在时返回 `null`，同名类型不唯一时会报错。

辅助程序集要在打包配置中明确选择；不要通过遍历所有已加载程序集，碰巧找到其他模组的同名类型。

## 4. 打开屏幕 UI

取得 `var ui = ModApi.For(Context).Ui;` 后，可以调用以下接口：

```csharp
ModUiSession OpenPanel(string prefabAddress, UnityEngine.Transform parent,
    bool useStack = true, bool useBg = false, bool useFadeTransition = false);

ModUiSession OpenView(string prefabAddress);

ModUiSession OpenPopup(string title, string msg,
    System.Action confirm, System.Action cancel = null);
```

| 接口 | 适用场景 |
| --- | --- |
| `OpenPanel` | 自选屏幕层级与打开方式；页面、信息条、提示层等 |
| `OpenView` | 使用页面层、背景和过渡的页面 |
| `OpenPopup` | 使用游戏标准样式的确认/取消弹窗 |

这些调用用于模组加载成功后的按钮或玩法逻辑，不能放在 `OnLoad()` 中。传入地址即可，游戏负责从当前模组加载和实例化作者 Prefab。

`OpenPanel` 的 `parent` 使用当前屏幕 Canvas 根，或它的直接 `Panel/View/Popup/Floating/Message` 层。不要传入作者临时创建的内容节点。作者自己的布局层级继续放在 Prefab 中。

覆盖层可以使用 `useStack: false, useBg: false`：

```csharp
var canvas = GetComponentInParent<UnityEngine.Canvas>();
var overlay = ModApi.For(session.Context).Ui.OpenPanel(
    "Art/Prefabs/Hud.prefab", canvas.transform,
    useStack: false, useBg: false);
session.Own(overlay);
```

此代码在已打开面板的组件中调用，`session` 为收到的会话，组件必须处于屏幕 Canvas 下。覆盖层不会自动在开局出现，也不会自动跟随游戏 HUD 的显隐；作者决定打开时机、布局和关闭时机。

作者 Prefab 的锚点、位置和大小会保留。全屏布局可使用全屏拉伸的 `RectTransform` 根；非交互图片或文字关闭 `raycastTarget`，避免透明区域遮挡游戏按钮。Pad 页面、玩法规则页和世界空间 UI 使用各自的接口，不通过这里登记。

`OpenPopup` 的确认与取消参数是无参数 `System.Action`。回调在弹窗关闭后执行；如果期间发生场景切换、UI 整体关闭或模组卸载，尚未执行的回调会被取消。

## 5. 管理 UI 会话

每次打开都会返回一个 `ModUiSession`，代表这次打开的界面。

| 成员 | 用途 |
| --- | --- |
| `Context` | 所属模组上下文 |
| `Instance` | 作者 Prefab 实例；标准弹窗不要依赖此属性 |
| `IsClosed` | 判断会话是否已关闭 |
| `Closed` | 关闭通知事件 |
| `Close()`、`Dispose()` | 关闭本次界面，可重复调用 |
| `Own(IDisposable)` | 让会话在关闭时释放订阅、资源句柄或子会话 |

作者组件实现 `IModUiPanel`，就可以取得会话并处理打开、关闭：

```csharp
using UnityEngine;
using UnityEngine.UI;
using WBS.Client.Logic.UI.ModUi;

public sealed class MyPanel : MonoBehaviour, IModUiPanel
{
    public Button CloseButton;
    private ModUiSession session;

    public void OnModPanelOpened(ModUiSession openedSession)
    {
        session = openedSession;
        CloseButton.onClick.AddListener(Close);
    }

    private void Close() => session?.Close();

    public void OnModPanelClosing()
    {
        CloseButton.onClick.RemoveListener(Close);
        session = null;
    }
}
```

把这个组件及 `CloseButton` 引用保存在 Prefab 中。静态控件无需在 `Awake`/`Start` 重新创建。

主面板打开的子界面可以交给主会话：

```csharp
var ui = ModApi.For(session.Context).Ui;
session.Own(ui.OpenView("Art/Prefabs/Details.prefab"));
session.Own(ui.OpenPopup("确认", "保存当前设置？", () => SaveSettings()));
```

这两段放在作者的按钮回调内，`SaveSettings()` 是作者自己的方法。主会话关闭时，其持有的子会话一起关闭；需要独立存在的界面则自行保存并关闭返回的会话。

界面关闭、所属场景退出、UI 整体回收或模组卸载时，所属实例、资源和会话订阅会被清理。关闭一个会话只影响它及其持有的内容。`OnModPanelClosing` 和 `Closed` 回调用于清理，不要在回调中立即打开新界面；需要继续打开时，等关闭流程结束后再执行。完整按钮与覆盖层例子见 [界面示例](https://github.com/MrAIMStein/WBS-MOD-SDK-PUBLIC/blob/main/Examples/WBSModExamples/Assets/Mod/WBSExampleUI/README.md)。

## 6. 联网代码

作者的联网行为使用 SDK 提供的 Mirror 类型，如 `NetworkBehaviour`、`[SyncVar]`、`[Command]`、`[ClientRpc]`。打包器会检查作者程序集是否完成 Mirror 代码生成，不要额外引入另一份 Mirror 运行库。

服务端必须决定操作是否合法：

- 从真实连接确定发送者，再检查其参赛权限、当前阶段和操作目标。
- 分数、回合结果和物品归属由服务端修改，不能信任客户端提交的身份或结果。
- `SyncVar` 用于公开状态。私密选择或数字保存在服务端，只给允许查看的玩家发送展示内容。
- 监听游戏或网络事件后，在对应的关闭、`Unload` 或销毁流程中解除订阅。

石头剪刀布示例在结算前只在服务端保存出手；计数器示例检查实际持有者，再增加次数并更新授权展示。联网模组发布前应使用相同模组包和不同 Steam 身份进行双客户端检查。

## 7. 自有资源和登记的清理

通常使用 `Resources` 和 UI 会话即可。需要管理额外资源时，可使用 `Context.Own<T>(resource)`，对象必须实现 `IDisposable`。`Context.Disposing` 在模组资源卸载前发出清理通知。

需要接入自己的登记系统时，可使用 `Context.StageRegistration(key, apply, rollback)`，并为登记提供对应撤销操作。直接修改全局静态字段、写文件或订阅外部事件，不会自动随登记失败回滚，作者必须处理其清理。

作者 DLL 更新后需要重新打包并重启游戏；不要依赖运行中替换文件完成热更新。

## 8. 注册 Harmony 补丁

完整 SDK 显式提供宿主使用的 `0Harmony`，程序集版本为 `2.2.2.0`。作者使用原生 Harmony API，在加载阶段登记一个同步回调：

```csharp
ModApi.For(Context).RegisterHarmonyPatches(harmony =>
{
    harmony.PatchAll(typeof(MyModMod).Assembly);
});
```

接口签名为 `void RegisterHarmonyPatches(System.Action<HarmonyLib.Harmony> apply)`。每个 `Context` 只能登记一次；需要多个补丁时，在同一回调中调用 `PatchAll`、`Patch` 或其他原生 API。`OnLoad` 中只登记回调，宿主提交登记时才创建 owner 为 `wbs.mod.<Context.UUID>` 的实例并同步执行回调。

回调中途抛出异常、后续登记失败或 `Context` 清理时，宿主按该 owner 撤销普通的 Prefix、Postfix、Transpiler 和 Finalizer。清理会逐个方法尝试，最后汇总异常，其他 owner 的补丁保留。Harmony 调用不逐项封装；补丁目标、签名、优先级和原生属性仍由作者指定。

只在同步回调中使用传入实例。作者自行创建实例，或保存实例在回调结束后继续添加补丁时，自行管理其生命周期。自动清理不恢复 ReversePatch、补丁已经改变的游戏状态、自建对象或外部订阅；这些状态通过 `Context.Own`、`Context.Disposing` 或作者自己的撤销逻辑处理。首版没有对局中异步补丁注册和热更新入口。

不要把另一份 `0Harmony.dll` 放进作者工程或模组成品。SDK 清单记录程序集身份与 SHA256，打包器按宿主程序集清单排除该 DLL。第三方声明见 [许可与素材署名](https://github.com/MrAIMStein/WBS-MOD-SDK-PUBLIC/blob/main/THIRD_PARTY_NOTICES.md)。[跳跃增强示例](https://github.com/MrAIMStein/WBS-MOD-SDK-PUBLIC/blob/main/Examples/WBSModExamples/Assets/Mod/WBSExampleJumpEnhancement/README.md) 同时演示提高高度和多段跳跃，并说明控制器私有字段的兼容边界。

## 9. 版本与加载失败

`RequiredModApiVersion` 表示模组需要的 API 版本，由打包工具填写。版本采用 `major.minor.patch` 三段数字，例如 `2.0.0`，不使用前导零或预发行后缀。

| 模组要求 | 游戏 API | 能否通过 API 版本检查 |
| --- | --- | --- |
| `2.0.0` | `2.0.0`、`2.1.0` | 可以 |
| `2.1.0` | `2.0.0` | 不可以，需要更新游戏 |
| `1.0.0` | `2.0.0` | 不可以，需要迁移模组 |
| 未填写 | 当前游戏 | 不可以，使用对应 SDK 重新打包 |

游戏还会检查最低游戏版本、依赖、程序集和资源。`MinGameVersion` 是可选的最低游戏发行版本，`Dependencies` 填写依赖模组的 UUID。联机需要双方使用相同的模组顺序、版本和内容，仅 API 版本相同还不够。

SDK 版本、API 版本与游戏版本分别维护；游戏更新并不一定要求作者重打包。处理方式见 [升级与游戏更新](升级与游戏更新.md)。请保留游戏随附的开发信息文件，让调试工具检查兼容性。

打包报告若提示使用“未承诺稳定的宿主接口”，表示代码还依赖公开 API 以外的游戏实现。可以使用这些接口，但游戏升级后要自行检查；反射或字符串调用也不保证兼容。玩法和物品示例包含此类调用，复制时请了解这项维护成本。

登记错误会指出出错的字段或资源。加载失败时先查看游戏模组管理页的原因和日志；编程工具也可读取 `ModManager.Diagnostics` 的 `UUID`、`KeyName`、`ModDiagnosticCode`、`Message`、`ExceptionType` 以定位问题。常见安装与打包问题见 [使用说明](使用说明.md)。
