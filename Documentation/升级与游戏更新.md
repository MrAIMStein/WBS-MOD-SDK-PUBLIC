# 游戏更新与模组升级

游戏更新后，先查看游戏的更新说明和 SDK 的版本说明。兼容的日常更新可以继续使用原来的 SDK 和模组成品，不需要每次重新打包。

## 先判断是否需要升级

| 遇到的变化 | 你需要做什么 |
| --- | --- |
| 游戏修复问题、增加玩法或更新内容，说明中没有模组迁移要求 | 继续使用已有 SDK 和模组成品，在新版游戏中确认自己的功能正常 |
| SDK 修复制作或打包工具 | 需要该修复时更新 SDK；已发布的模组成品不会因此自动改变 |
| 你要使用新接口 | 安装提供该接口的 SDK，修改代码并重新打包；确认模组声明了所需的 API 版本 |
| SDK 更新了人物模板 | 需要新模板时，对已有制作配方执行“刷新到当前模板”，检查人物后重新打包 |
| SDK 更新了公共 Shader | 更新 SDK 后检查材质外观；需要发布该变化时重新打包 |
| 更新说明要求迁移 API、人物组件或 Unity 工具链 | 按对应迁移说明修改工程，重新编译和完整打包 |

版本号各有用途，不需要彼此相等：

| 版本 | 用途 |
| --- | --- |
| 游戏版本 | 标识玩家正在使用的游戏发行版 |
| SDK 版本 | 标识制作工具、编译所用 DLL 和公共资源；同一版本可以支持多个游戏版本 |
| 模组 API 版本 | 标识模组使用的接口要求；由 `RequiredModApiVersion` 声明 |

模组自身的 `Version` 由你维护。发布新的内容或修复时提高它，便于玩家确认安装了哪个版本。游戏提示的推荐 SDK 版本用于选择工具，不要求 SDK 与游戏版本同号。API 兼容要求见 [接口参考](接口协议.md)。

## 更新作者工程

1. 备份或提交源工程，保留旧模组成品。一起保存 `Assets` 中的资源及其 `.meta`、制作配方和打包配置。
2. 下载需要的 SDK Release，按 [安装说明](SDK安装.md) 更换完整 SDK 包。使用该 Release 指定的 Unity 和配套依赖版本。
3. 等待 Unity 完成导入和编译。先处理 Console 中的错误，再打开制作和打包工具。
4. 根据更新说明处理源码或人物模板。没有模板升级要求时，不必重新生成人物。
5. 完成下面的检查后，提高模组版本并发布完整的新模组目录。打包流程见 [制作与打包指南](使用说明.md)。

升级已有模组时，保留它的 UUID、KeyName、人物 ModelId 和已有成品的 `.meta`。这些信息用于识别同一个模组和人物；制作新模组才使用新的身份。

## 更新人物模板和材质

在 `WBS/角色/角色制作工具` 中选择原来的 `Recipe.asset`：

- **生成完整人物**：用配方更新模型与材质，保留已有的游戏人物包装结构。
- **刷新到当前模板**：用当前 SDK 的人物模板重建包装结构，保留人物身份、输出 GUID、模型和材质配置。

如果成品曾被手工修改，工具可能报告差异并停止覆盖。先查看差异，将需要保留的调整落实到源模型、材质或配方，再尝试生成。不要删除成品、删除 `.meta` 或清空制作记录来绕过提示。旧制作记录无法安全迁移时，保留原工程和成品，按迁移说明重新建立配方。

作者材质保存在自己的模组目录中，更新 SDK 不会重置这些材质。公共 Shader 更新仍可能影响外观，因此要在游戏中检查光照、透明、裁切和描边。旧 `UGL/Toon` 的转换会报告无法等价转换的参数；自定义 Shader 则需要确认目标平台能够正常渲染。

## 发布更新前检查

人物模组需要查看选择预览、正式角色、头像和遗体，检查动画、视角、持物、碰撞、倒地和材质。代码模组需要检查自己的玩法、物品和界面功能，以及离开场景、结束对局和卸载时的清理。

联机模组还应使用两台设备和两个 Steam 账号验证实际运行。房间成员需要安装相同的模组版本与内容，并保持一致的启用顺序。

如果更新涉及不兼容的 API 主版本，旧包不能仅靠修改 `modinfo.json` 的版本字段迁移。完成源码和资源迁移后，重新发布完整目录，并让玩家退出游戏再替换原目录。玩家安装步骤见 [制作与打包指南](使用说明.md)。
